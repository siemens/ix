# Breaking Changes V6

This document lists breaking changes introduced in Siemens Industrial Experience V6.

## React callback types

The React wrapper now uses `unknown` instead of `any` for untyped public values:

- `closeModal`, `ModalRef.close`, and `ModalRef.dismiss` default their result
  type to `unknown`.
- `IxTreeProps.renderItem` receives `unknown`.
- `IxTreeProps.onNodeRemoved` receives `CustomEvent<unknown[]>`.

Specify generic result types where needed and narrow callback values before
accessing their properties.

## Vue modal types

The Vue wrapper now uses `unknown` instead of `any` for untyped modal close reasons:

- `closeModal` defaults its reason type to `unknown`.

Specify generic reason types where needed or narrow the reason value before accessing its properties.

## Stencil collection optional peers

The Stencil collection has four newly optional peer dependencies:
`@floating-ui/dom`, `animejs`, `luxon`, and `@stencil/core`.
`@siemens/ix-icons` remains a required peer. Collection metadata and output
consumers must install all five packages:

```sh
pnpm add @floating-ui/dom @siemens/ix-icons @stencil/core animejs luxon
```

Use the equivalent command for npm, pnpm, or another package manager.
`@siemens/ix-icons` remains required for all `@siemens/ix` consumers. Root,
custom-elements, loader, hydrate, and framework consumers do not need to install
the other four optional peers solely for IX because those outputs bundle the
runtime libraries.

## Siemens design tokens

IX components now use SI Theme 6 system and reference tokens instead of legacy
IX `--theme-*` tokens. This is a semantic migration, not a prefix removal:
select a purpose-specific background, border, or text token for each use.
Semantic color tokens use the `--si-sys-color-*` namespace.

The mappings below use code-facing CSS custom-property names. Source hierarchy
paths have been flattened to the legacy `--theme-*` and new `--si-sys-*` syntax;
trailing `*` markers in the source mapping are metadata and are omitted here.
The existing typography and shadow examples map as follows:
`--theme-body` -> `--si-sys-typography-body` and `--theme-shadow-4` ->
`--si-sys-color-effects-shadow-4`.

Replace legacy token references according to how the value is used. For
example:

```css
/* Before */
color: var(--theme-color-std-text);

/* After */
color: var(--si-sys-color-text-primary);
```

Sass code can use the new public system-token module:

```scss
@use '@siemens/ix/scss/tokens/system' as sys;

color: #{sys.$si-sys-color-text-primary};
```

### Token value shapes

Replacement tokens are not guaranteed to have the same CSS value type as the
legacy token. `--si-sys-color-effects-shadow-*` tokens contain a complete
`box-shadow` value, including offsets, blur/spread where applicable, and color.
Assign a complete shadow token directly to `box-shadow`. Do not mechanically
substitute one where a legacy `--theme-color-shadow-*` token supplied only the
color component of a longer shadow declaration; these color tokens have no
direct replacement and require manual reconstruction or review. Likewise,
`--si-sys-typography-*` tokens contain complete `font` shorthand values, so use
them with `font`, not as a `font-family` or size fragment.

The `ix-typography` formats `label`, `label-xs`, `label-sm`, `label-lg`,
`body-xs`, `display-xs`, and `display-sm` have no SI Theme 6 system-token
equivalent and were removed. Replace label formats with the closest `body`,
`body-sm`, or `body-lg` format. For removed display formats, choose a supported
display or heading format based on the intended hierarchy.

```css
/* A complete shadow token can be replaced directly. */
/* Before */
box-shadow: var(--theme-shadow-4);

/* After */
box-shadow: var(--si-sys-color-effects-shadow-4);

/* Do not mechanically replace a legacy color component this way. */
/* Before */
box-shadow: 0 2px 4px var(--theme-color-shadow-1);

/* Incorrect */
box-shadow: 0 2px 4px var(--si-sys-color-effects-shadow-1);
```

### Removed shadow utility aliases

The legacy shadow utility module `scss/utilities/_shadows.scss` and its nine
`--theme-box-shadow-*` CSS custom-property aliases have been removed.
The utilities, globals, and legacy stylesheets no longer declare these aliases.
Remove direct Sass imports of the deleted module and use the complete system
shadow tokens directly with `box-shadow`.

| Removed aliases | System replacement |
| --- | --- |
| `--theme-box-shadow-lvl-1`, `--theme-box-shadow-level-1` | `--si-sys-color-effects-shadow-1` |
| `--theme-box-shadow-lvl-2`, `--theme-box-shadow-level-2` | `--si-sys-color-effects-shadow-2` |
| `--theme-box-shadow-lvl-3`, `--theme-box-shadow-level-3` | `--si-sys-color-effects-shadow-3` |
| `--theme-box-shadow-lvl-4`, `--theme-box-shadow-level-4` | `--si-sys-color-effects-shadow-4` |
| `--theme-box-shadow-insert` | No system-token successor |

```css
/* Before */
box-shadow: var(--theme-box-shadow-level-4);

/* After */
box-shadow: var(--si-sys-color-effects-shadow-4);
```

System shadow values follow the SI Theme 6 elevation design and can render
differently from the legacy values.

The `--theme-box-shadow-insert` alias previously resolved to
`--theme-inset-shadow-1`, which has no SI Theme 6 inset-shadow successor.
Remove usages of the removed alias or provide an application-defined inset
shadow. Do not replace an inset effect with an outer elevation-shadow token.
Legacy shadow definitions, including `--theme-inset-shadow-1`, have also
been removed from generated themes.
Input-like components, shared input mixins, and legacy native inputs no longer
consume it. Decorative `box-shadow` declarations and redundant `none` resets
have been removed, including hover and focus states.
The `--ix-input--box-shadow`, `--ix-select--box-shadow`,
`--ix-chat-input--box-shadow`, and `--ix-expanding-search--box-shadow`
properties have also been removed; setting them no longer changes these
controls. No replacement is provided because input-like controls have no
decorative shadow. Keyboard-focus outlines and the browser autofill background
correction are unchanged.

### Removed common dimension and typography tokens

Generated themes no longer include legacy common variables for sizing,
spacing, container dimensions, text decoration, shadow geometry, font sizes
and weights, line heights, or letter spacing. The unused branding asset alias
and duplicated `--theme-focus--outline-offset` have also been removed.
The common theme mixin now retains only the five timing compatibility
variables.

| Removed variables | Migration |
| --- | --- |
| `--theme-size-*`, control heights, icon sizes, and input minimum width | Select purpose-specific `--si-sys-sizing-size-*` or `--si-sys-sizing-icon-*` tokens. |
| `--theme-space-*` and `--theme-input-padding-*` | Use `--si-sys-sizing-spacing-x-*` and `--si-sys-sizing-spacing-y-*` for the corresponding axes. |
| `--theme-container-size-*` | Select a suitable system sizing token or an application-defined layout width; there is no universal one-to-one mapping. |
| `--theme-ms-*`, `--theme-font-size-*`, `--theme-font-weight-*`, `--theme-line-height-*`, and `--theme-letter-spacing-*` | Use a supported `--si-sys-typography-*` role with `font`. Use reference font weights when a separate weight override is needed. Do not assign a complete typography token to `font-size`. |
| `--theme-text-decoration-*` | Use CSS `none`, `underline`, or `line-through`; no system-token replacement is provided. |
| Legacy shadow geometry variables and `--theme-shadow-1` through `--theme-shadow-4` | Use the corresponding complete `--si-sys-color-effects-shadow-*` token directly with `box-shadow`. |
| `--theme-inset-shadow-1`, inner-shadow geometry, `--theme-lightbox-blur`, and `--theme-overlay-blur` | No clean system-token replacement; remove the effect or provide an application-defined value. |
| `--theme-logo--siemens` | Use an application-provided logo asset; no system-token replacement is provided. |
| `--theme-focus--outline-offset` | Use `--si-sys-sizing-focus-ring-offset`. |

Unused legacy typography shorthands, including `--theme-body`, `--theme-h*`,
`--theme-code*`, and `--theme-text-*`, have also been removed from Classic
themes. Use the supported system typography roles instead.

The remaining chat, checkbox, and event-list token consumers have been
migrated. Default spacing and chat font sizes are preserved; compact density
now also applies to the migrated chat spacing, chat typography, and checkbox
label gap. Component-scoped `--ix-*` overrides remain supported.

### Common border, radius, and focus overrides

Built-in components, shared input mixins, legacy native-input styles, and
AG Grid theme parameters now consume system sizing tokens instead of the
common geometry variables below. These legacy declarations have been removed
from the common theme mixin.
Migrate global overrides and application styles to the matching system token,
or retain a supported component-scoped `--ix-*` override.

| Legacy variable | System replacement |
| --- | --- |
| `--theme-border-width-default` | `--si-sys-sizing-border-width-default` |
| `--theme-border-width-none` | `--si-sys-sizing-border-width-none` |
| `--theme-border-width-thick` | `--si-sys-sizing-border-width-selected` |
| `--theme-focus--border-thickness`, `--theme-focus-border-thickness` | `--si-sys-sizing-border-width-default` |
| `--theme-focus-outline-offset` | `--si-sys-sizing-focus-ring-offset` |
| `--theme-default-border-radius` | `--si-sys-sizing-border-radius-sm` |
| `--theme-small-border-radius` | `--si-sys-sizing-border-radius-xs` |
| `--theme-min-border-radius` (already unused by IX) | `--si-sys-sizing-border-radius-none` |

These replacements preserve existing widths, radii, and focus offsets in
default and compact density. Both legacy focus-border variables describe a
`0.0625rem` border, not the `0.125rem` system focus-ring width; substituting
`--si-sys-sizing-focus-ring-width` would change their appearance.

The five `--theme-*-time` variables remain in use by animation styles and the
runtime duration lookup. The current system-token catalog has no duration
successors, so these timing overrides remain supported.

#### Monospace font family

The reset styles for `<pre>`, `<code>`, `<kbd>`, and `<samp>` now use
`--si-ref-typography-font-family-mono` instead of `--theme-font-code`.
The classic theme defines this reference token as `'Courier New', monospace`,
replacing the legacy `'JetBrains Mono'` default. Override the reference token
to customize the monospace font in the reset, globals, and legacy stylesheets.

- `background-color`, `background`, or a shape/surface `fill`: use
  **Background/fill**.
- `border-color`, `border`, or `outline`: use **Border/outline**.
- `color` on text or icons, or an icon SVG `fill`: use **Text/icon**.

background/fill use. An em dash means the source guide defines no replacement
for that context.

## ECharts computed CSS properties

The `getComputedCSSProperty` helper exported by `@siemens/ix-echarts` no longer
adds the `--theme-` prefix to its argument. It now resolves the supplied CSS
custom-property name without modification.

Pass the complete SI Theme 6 system-token name, including the leading `--`:

```ts
// Before: resolves --theme-color-primary
getComputedCSSProperty('color-primary');

// After
getComputedCSSProperty('--si-sys-color-background-accent');
```

Replace every legacy short token name with its mapped system token. Select the
appropriate background, border, or text token for conditional mappings based on
how ECharts renders the value.

component-token layer, all 1,557 aliases, and their system-token replacements or

## Global CSS and Sass entry points

The default `siemens-ix.css` stylesheet now contains the combined classic theme
and IX foundation. Foundation applies body typography, text color, background,
and document-wide scrollbar styles. It does not normalize native HTML elements,
reset the body margin, style native links or form controls, or provide utility
classes.

Use the canonical default import for self-contained IX components:

```css
@import '@siemens/ix/css/default.css';
```

The existing `@siemens/ix/dist/siemens-ix/siemens-ix.css` import path remains
available and resolves to the same default bundle. It includes the foundation
body and scrollbar defaults but not the previous reset, utility, or native form
styles.

Global application styles are available as explicit opt-ins:

| Import                           | Side effects                                                 |
| -------------------------------- | ------------------------------------------------------------ |
| `@siemens/ix/css/foundation.css` | Required variables, body presentation, and global scrollbars |
| `@siemens/ix/css/reset.css`      | Native element normalization and box sizing                  |
| `@siemens/ix/css/base.css`       | Theme font/color inheritance and body margin reset           |
| `@siemens/ix/css/scrollbar.css`  | Scoped scrollbars below `[data-ix-scrollbars]`               |
| `@siemens/ix/css/utilities.css`  | Typography, links, tables, groups, and shadows               |
| `@siemens/ix/css/globals.css`    | Reset, base, scrollbar, and utilities                        |
| `@siemens/ix/css/legacy.css`     | Previous native form and global style behavior               |

### Typography utility classes

The v6 typography utilities remove `.typography-label`,
`.typography-label-xs`, `.typography-label-sm`, `.typography-label-lg`,
`.typography-body-xs`, `.typography-display-xs`, and
`.typography-display-sm`. Replace these classes in application markup:

| Removed class | Migration |
| ------------- | --------- |
| `.typography-label`, `.typography-label-xs`, `.typography-label-sm`, `.typography-label-lg` | Use `.typography-body`, `.typography-body-sm`, or `.typography-body-lg` based on the intended text size. |
| `.typography-body-xs` | Use `.typography-body-sm` for small body text; there is no extra-small system typography format. |
| `.typography-display-xs`, `.typography-display-sm` | Choose a supported `.typography-display`, `.typography-display-lg`, or `.typography-h1` through `.typography-h6` class based on the intended hierarchy. |

For paragraphs, use the new `.typography-body-paragraph` utility (or
`.typography-body-paragraph-sbold` for semibold text) rather than relying on a
removed label class or a generic body style. The same format names are
available on `ix-typography`. Import `@siemens/ix/css/default.css` or
`@siemens/ix/css/utilities.css` to load these utility classes; importing
`@siemens/ix/css/legacy.css` does not restore the removed selectors.

Import foundation before a separately selected theme:

```css
@import '@siemens/ix/css/foundation.css';
@import '@siemens/ix/css/theme/classic-light.css';
```

To retain the previous aggregate behavior while migrating, combine the new
default and legacy bundles:

```css
@import '@siemens/ix/css/default.css';
@import '@siemens/ix/css/legacy.css';
```

Applications that keep the existing distribution path can restore the same
behavior with:

```css
@import '@siemens/ix/dist/siemens-ix/siemens-ix.css';
@import '@siemens/ix/css/legacy.css';
```

Foundation styles enable scrollbars automatically. Add `disable-scrollbar` to
`body` to disable that behavior. The scoped scrollbar stylesheet can then
enable themed scrollbars for a selected subtree:

```html
<body class="disable-scrollbar">
  <main data-ix-scrollbars>
    <!-- Scrollable descendants use IX scrollbar styling. -->
  </main>
</body>
```

The package no longer exports every file below `@siemens/ix/scss/*`. Supported
Sass entry points are now explicit and mirror the CSS bundles:

```scss
@use '@siemens/ix/scss/default';
@use '@siemens/ix/scss/globals';
@use '@siemens/ix/scss/tokens/system' as sys;
```

Theme modules and retained public mixins remain explicitly exported. The
`@siemens/ix/scss/deprecated/components` export has been removed. Replace
imports from internal `components`, `entries`, `legacy`, `misc`, and
`mixins/internal` folders with a supported public entry point or local styles.
The former `@siemens/ix/scss/misc/common-variables` path remains as a v6
compatibility export for generated custom themes; new Sass code should use
`@siemens/ix/scss/tokens/legacy`.

## Content header text wraps by default

`ix-content-header` titles and subtitles now wrap when horizontal space is limited. Previously, they remained on a single line and used an ellipsis for overflowing text.

To preserve the previous single-line behavior, set `text-overflow="ellipsis"`:

```html
<ix-content-header header-title="Content title" header-subtitle="Supporting context" text-overflow="ellipsis"></ix-content-header>
```

Ellipsis visually truncates the text without adding a tooltip. Keep the default wrapping behavior when the complete text must remain visible.

### Validation checklist

1. Every `ix-content-header` that must remain single-line uses `text-overflow="ellipsis"`.

## Date Time Picker - locale support

Locale support was extended to date-time values and headers, so the return value strings will now be localised.

The `from` and `to` fields on `DateChangeEvent` (emitted by `ix-date-picker`, `ix-date-dropdown`) and `from`, `to`, and `time` on `DateTimeSelectEvent` (emitted by `ix-datetime-picker`) were previously always formatted using the `en-US` locale, regardless of the `locale` prop. They now reflect the locale set on the component.

If your code reads these fields and expects locale-neutral strings, migrate to the new `isoFrom`, `isoTo`, and `isoTime` fields, which always contain ISO 8601 values independent of locale.

**Note**: If you pass a `format` string, ensure to use localized formats ([see supported formats table](https://moment.github.io/luxon/#/formatting?id=table-of-tokens)) tokens in order to ensure locale-specific rendering of the date-time values.

**New fields added to event types:**

- `DateChangeEvent`: `isoFrom?: string`, `isoTo?: string`
- `DateRangeChangeEvent`: `isoFrom?: string`, `isoTo?: string`
- `DateTimeSelectEvent`: `isoFrom?: string`, `isoTo?: string`, `isoTime?: string`

  **New props:**

- `ix-time-picker` and `ix-time-input`: `locale`, `i18nAm`, and `i18nPm`
- `ix-datetime-picker`: `i18nAm`, `i18nPm`, `i18nHourColumnHeader`, `i18nMinuteColumnHeader`, `i18nSecondColumnHeader`, and `i18nMillisecondColumnHeader`

**New methods:**

- `ix-time-picker`: `getCurrentIsoTime(): Promise<string | undefined>` — returns the current time as an ISO 8601 string, independent of the `locale` prop

**Updated `ix-date-input` locale behavior:**
The `locale` prop now explicitly affects input parsing and the values emitted via `valueChange`. Previous documentation incorrectly stated that locale does not affect returned values.

## Default icon size is 20

Omitted icon `size` on **ix-icon-button**, **ix-icon-toggle-button**, and nested icons that inherit that default now renders a **20px** glyph instead of **24px**. The control host for size `20` and `24` remains **32×32**. Size `20` is also available as an explicit public value.

Most composed components follow the same omit→20 default. A smaller set of chrome icons stay on an intentional larger or smaller size (pinned in code). Treat **Figma** as the source of truth for which slots are 16 / 20 / 24 / 32; do not use this document as a size catalog.

**ix-checkbox** and **ix-radio** control glyphs also move to **20** (hit area stays 24×24). Legacy `.ix-form-control` checkboxes align to the same outer size.

```html
<!-- Before (omit → 24px glyph) -->
<ix-icon-button icon="rocket"></ix-icon-button>

<!-- After (omit → 20px glyph) -->
<ix-icon-button icon="rocket"></ix-icon-button>

<!-- Keep the previous 24px glyph -->
<ix-icon-button icon="rocket" size="24"></ix-icon-button>
```

### Migration checklist

1. Visually review screens that relied on omitted icon `size` for a 24px glyph.
2. Set `size="24"` (or the previous explicit size) wherever the previous glyph must remain.
3. Prefer omitting `size` when the new 20px default matches the design; do not hardcode `size="20"` in product code.
4. For intended sizes on composed chrome (headers, menu, tabs, etc.), follow the current Figma specs rather than assuming every icon moved to 20.
